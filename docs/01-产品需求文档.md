# 01 · 产品需求文档（PRD）

**版本**：v2.0（Nuxt 重建后重写）｜ **基准日期**：2026-11-04 ｜ **状态**：已上线 `https://dirtool.com`

> 本文描述**产品要什么**。实现怎么做看 [`02-技术架构.md`](02-技术架构.md)，接口细节看 [`03-API接口文档.md`](03-API接口文档.md)。

## 1. 一句话定位

**一个双语 AI 产品目录站，靠「卖收录」和「卖周广告位」赚钱。**

不是媒体、不做评测、不写长文。用户来这里的目的很具体：**找某个用途的 AI 工具**，或者**把自己的产品挂上去被找到**。

---

## 2. 为什么做这个

**问题**：AI 工具每周新增几百个，但发现渠道被少数几个大目录站垄断。小团队的产品想被看到，要么排队等编辑收录，要么买很贵的推广位。

**机会**：

- 目录站的 SEO 价值极高——「best AI tools for X」这类词长期有搜索量，且意图明确
- 收录是**一次性付费**，用户决策成本低，不需要订阅心理门槛
- 广告位可以按周卖，比月付更容易成交，也能验证真实流量

**我们的差异**：不编假数据。竞品右栏写「2,422 founders visited, up 103%」，我们不写这种数字——站上每个数字都能追溯到真实记录。

---

## 3. 目标用户

### 3.1 三类角色

| 角色 | 占比预期 | 核心诉求 | 入口 |
|---|---|---|---|
| **找工具的人**（访客） | 90% | 快速找到能解决某个问题的工具，不踩坑 | `/`、`/tools`、搜索、分类 |
| **提交者**（产品方） | 9% | 让产品被目标用户看到，且能被 Google 收录 | `/submit`、`/settings/*` |
| **站长**（运营方） | 1% | 审稿、收款、排广告、看数据 | `/admin?token=…` |

### 3.2 提交者画像（付费决策人）

- 独立开发者 / 3–10 人小团队的产品负责人
- 产品已上线，有官网和一句话介绍，缺流量
- 预算敏感但愿意为「确定的曝光」付一次性费用
- 判断标准：**这个站有没有真实流量、能不能被搜到**

> 这条画像直接决定了两件事：① 必须有真实 DR / 访问数据可展示，否则卖不动；② 定价必须是一次性，订阅会被直接拒掉。

## 4. 核心场景

### 场景 A：访客找工具

```
Google 搜「AI tool for podcast editing」
  → 落地 /categories/audio 或 /tools/podcast-xxx
  → 看列表卡片（名称 / 一句话 / 标签 / 票数）
  → 点进详情页看长描述、定价、相似推荐
  → 点「Visit site」跳转官网
```

**设计要求**：3 次点击内到达任何产品；详情页必须能独立承接搜索流量（有结构化数据、FAQ、面包屑）。

### 场景 B：提交者提交产品

```
/submit
  → 第 1 步：粘贴官网 URL（POST /api/fetch-meta 抓 title / description 预填）
  → 第 2 步：确认名称、一句话、分类、标签、长描述
  → 第 3 步：选套餐（Free / Standard / Featured / Pro / 广告位）
  → POST /api/submit → 记录为 pending（付费档同时标 awaiting_payment=1）
  → 收到确认邮件（需配邮件密钥）
  → 免费档：站长人工审核 → 上线；付费档：Waffo 付款成功 → 回调验签 → 自动发布上线
  → 再发一封邮件
```

**返回的 `next` 字段告诉前端该显示哪个屏幕**：`review`（免费，进审核队列）或 `paid`（付费，等在线付款完成）。**付费档付款成功后由回调自动发布，不等人工确认收款**（2026-11-08 起，见 `08-在线支付接入.md`）。说「已发布」而实际上还要人看一眼，是目录站第一天就失去信任的方式。

### 场景 C：站长日常

```
/admin?token=…
  → 审核队列：批准 / 拒绝（填理由）
  → 待付款队列：确认收款 → 当天上线
  → 周广告位：录入排期 / 立即下架
  → 收录管理：置顶 / 下架
```

### 5.1 内容与浏览

| 标签页 | 15 个：`api` `agent` `chatbot` `video-generation` `image-generation` `search` `app-builder` `code-assistant` `writing` `avatar` `music` `open-source` `meeting` `presentation` `text-to-speech` | ✅ |
| 产品详情 | 长描述、标签、相似推荐、AI 引擎直达链接、FAQ、结构化数据 | ✅ |
| 开发者页 | 从产品自动聚合 maker；已上线提交的 maker 也会出现 | ✅ |
| 周榜 `/weekly` | 按 ISO 周（周一起算）；登录后每人每周一票；按票数重排；上周归档 | ✅ |
| 最新收录 `/just-added` | 精选最新 + 已上线提交，按时间倒序 | ✅ |
| 全站搜索 | 客户端索引，打开时按需拉一次已上线提交 | ⚠️ 新建提交后需重新打开搜索框 |
| 中英切换 | 两套完整页面树（`/` 与 `/zh`），非机翻 | ✅ |
| SEO 诊断 `/seo-check` | 页面在、导航在，但调用的 `/api/audit` 与 `/api/dr` **未实现** | ❌ 见 06 文档 P1-1 |

### 5.2 提交与账号

**提交表单字段规格（服务端强校验，前端校验只是体验）**

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `url` | ✅ | 合法域名，不能与已有条目重复 | 自动提取 `domain` 做去重键；`www.` 会被去掉，所以 `www.foo.com` 与 `foo.com` 算同一个站 |
| `name` | ✅ | 2–60 字符 | 产品名 |
| `short` | ✅ | 20–200 字符，**不能含链接** | 一句话介绍 |
| `long` | ❌ | 120–4000 字符，不能含链接 | 详情页长描述 |
| `category` | ✅ | 必须是已有 8 个分类之一 | 不接受自造分类 |
| `tags` | ❌ | 最多 4 个，必须命中已有标签 | 传 slug 或英文名都行；不在词表里的静默丢弃 |
| `email` | ❌ | 合法邮箱格式 | 用于回复与通知；**不填就收不到任何邮件** |
| `logo` | ❌ | 必须 http(s) 开头 | 不合法则清空，页面回落到首字母图标 |
| `plan` | ✅ | free / standard / featured / pro / ad | 未知值一律降级为 free |
| `slot` | 条件 | 仅 `plan=ad` 时有效：board / sidebar | 决定广告位位置；不填则站长看不出买的是哪个位 |
| `maker` | ❌ | 0–60 字符 | 开发者 / 团队名 |

**限流与配额**

| 规则 | 值 |
|---|---|
| 单 IP 每小时提交 | 5 次 |
| 单 IP 每天提交 | 20 次 |
| 全站存储上限 | 20,000 条 |
| 同一域名 | 只能有一条 pending 或 approved 的提交 |

**账号**

- Google OAuth 2.0（Authorization Code + 签名 state cookie 防 CSRF）
- 会话：HMAC 签名的 `atlas_session` cookie，30 天，HttpOnly / Secure / SameSite=Lax
- **没有用户表**：会话自包含，服务端只存签名密钥
- 未登录也能提交，但记录不绑定账号 → 「我的提交」看不到
- 登录后：可看自己的提交与付款记录
- ❌ **不能自己编辑已上线的提交**（旧站有这功能，Nuxt 版没移植）。用户要改文案只能发邮件
- 个人资料页**只读**：昵称与头像来自 Google，页面不假装能改

### 5.3 商业化

**四档收录（一次性）** —— 数字的唯一来源是 `nuxt/shared/content/pricing.ts`

| 套餐 | 价格 | 权益 |
|---|---|---|
| Free | $0 | 人工审核（通常 7–14 天，不保证）；目录 + 分类展示；**nofollow** 链接；永久保留，可参与周榜 |
| Standard | $19 | 付款成功后自动收录发布；**永久 dofollow**；目录页排在免费之前；不挂 badge、不复查 |
| Featured | $39 | Standard 全部 + 目录与分类页置顶 7 天 + 首页精选卡排期；7 天后回落 Standard 排序，链接不变 |
| Pro | $69 | Featured 全部 + 分类页置顶 90 天 + 全年 4 次文案修改 + 开启邮件后 24h 回复 |

**周广告位（按周）**

| 位置 | 单价 | 连投 4 周 | 说明 |
|---|---|---|---|
| 榜单位 `board` | $29 / 周 | $99 / 4 周（省 $17） | 插入周榜第 3 名之后，整行 |
| 右栏位 `sidebar` | $19 / 周 | $65 / 4 周（省 $11） | 首页与「最新收录」页右栏顶部卡片 |

广告位规则：

- 外链一律 `rel="sponsored nofollow noopener"`——付费链接传权会让全站编辑链接贬值
- **到期自动下架**：有效期是数据的属性，不需要跑任何任务
- 可随时手动下架，**记录保留**（发票是照这些日期开的）

**支付**：❌ 无网关。当前是「用户选付费档 → 记录标为待付款 → 站长线下收款 → 后台点确认收款 → 当天上线」。

### 5.4 SEO

| 功能 | 规格 |
|---|---|
| 结构化数据 | WebSite / ItemList / SoftwareApplication / FAQPage / BreadcrumbList / Organization |
| `sitemap.xml` | 运行时生成，每页 en + zh 两个 `<url>`，各带完整 hreflang 三件套；含已上线提交，排除已下架 |
| `robots.txt` / `llms.txt` | 运行时生成 |
| canonical / hreflang | 中英互指，`x-default` 指向英文 |
| 旧 URL 迁移 | 全部 `.html` 地址 301 到无后缀路径，查询串保留 |
| 单一主域 | `www` 与 `http` 一律 301/308 到 `https://dirtool.com`；预览子域带 `noindex` |
| SEO 诊断工具 | ❌ 未实现（页面在，接口没有） |
| DR 域名权重 | ❌ 未接入 |

### 5.5 后台

| 功能 | 规格 |
|---|---|
| 门禁 | `/admin?token=…` 种 cookie 并立刻从 URL 移除 token；**无令牌返回 404 而非 403** |
| 审核队列 | 读服务端；批准 / 拒绝（可填理由，拒绝记录保留） |
| 待付款队列 | 显示套餐金额；「确认收款」是唯一跳过编辑判断的发布路径；**付费档未付款时「批准」会被拒（409）** |
| 广告位排期 | 表单录入、列表、立即下架；**保存即生效**，不需要重建 |
| 收录置顶 | 写 `tool_overrides`，可设到期日；**立即生效** |
| 收录下架 | 写 `tool_overrides`，详情页**立即 410**，列表与 sitemap 立即消失 |

> 注意「立即生效」这四个字：旧站有一半功能是「下次构建生效」，现在全部是写库即生效。这是重建带来的最实质的改变。

## 7. 成功指标

### 7.1 北极星指标

**付费收录数 / 月**。它同时反映流量质量、转化路径和产品说服力。

### 7.2 分层指标

| 层 | 指标 | 现在能测吗 |
|---|---|---|
| 流量 | 自然搜索 UV、收录页数 | ✅ 域名已切，站点已可被索引（数据要等 Search Console 攒） |
| 参与 | 提交数、投票数 | ✅ 服务端有记录（`submissions` / `votes`） |
| 转化 | 免费 → 付费转化率、客单价 | ✅ `submissions.plan` + `paid_at` 可数 |
| 留存 | 提交者复购（买第二周广告） | ✅ `ads` 表可查 |
| 健康 | 审核积压天数、邮件送达率 | ⚠️ 前者可数（`pending` 的 `created_at`）；后者需配邮件密钥 |

**怎么查：**

```bash
cd nuxt
npx wrangler d1 execute product-atlas --remote --command \
  "SELECT plan, COUNT(*) n FROM submissions WHERE paid_at IS NOT NULL GROUP BY plan"
```

### 7.3 阶段性目标（建议）

| 阶段 | 目标 |
|---|---|
| 上线 0–1 月 | 30 个种子产品、自然流量破 100 UV/天 |
| 1–3 月 | 累计 10 笔付费收录、1 个广告位客户 |
| 3–6 月 | 月收入稳定覆盖成本、DR 破 20 |

## 8. 明确不做（非目标）

写下来是为了防止反复讨论：

| 不做 | 原因 |
|---|---|
| 评论 / 评分 | 需要审核成本和防刷机制，收益远低于维护成本 |
| 收藏 / 关注 | 需要账号体系深度绑定，当前用户量撑不起 |
| 订阅制 | 提交者明确抗拒；一次性付费决策成本低 |
| 自建支付 | 早期单量小，人工收款更划算；量起来后接 Stripe/Paddle |
| 编辑团队 / 原创评测 | 人力密集，且与「目录」定位冲突 |
| 移动 App | 站点已响应式，App 无增量价值 |
| 工单系统 | 联系页足够。做一个写不到任何地方的工单表单，比直接给邮箱更糟 |
| 用户自定义头像 | Google 是身份源。做一个只写 localStorage 的上传器是假功能 |

## 9. 约束与风险

| 约束 | 影响 | 应对 |
|---|---|---|
| 内容在构建期（`catalog.json`） | 加产品要改文件 + 重新部署 | 这是刻意的：精选内容不该能被人从后台改掉。社区提交走数据库，不受影响 |
| D1 单库 | 无法水平分片 | 本站量级（万级行）远未到上限 |
| 无支付网关 | 无法规模化收款 | 量起来后接 Stripe/Paddle |
| 会话无状态 | 无法立即吊销某个会话 | 寿命 30 天，payload 只含公开资料 |
| 邮件依赖第三方 HTTP API | 密钥错/发件域未验证 → 全部静默跳过 | 上线后跑一次 `wrangler tail` 确认 `[mail]` 没有报错 |
| 没有自动化测试 | 回归靠手动清单 | 见 [`05-测试与验收.md`](05-测试与验收.md) §D |
