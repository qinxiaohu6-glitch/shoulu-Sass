## 一、现状问题与本次结论

站里原本有两套互相打架的说法：

| 位置 | 旧说法（错） | 生产实际 |
|---|---|---|
| 首页 / `/pricing` / `/rules` / `/faq` / 法务页 / 邮件 / 后台提示 / 服务端错误文案 | 「付款确认后当天上线（人工确认收款）」「we confirm receipt by hand」 | Waffo webhook 验签 → `settleOrder()`（`WHERE status='pending'` 幂等）→ Listing `confirmPayment()` 自动发布 / Ad `activateAdBooking()` 自动排期 |
| `/submit` 表单、`/book-ad` | 「付款成功后立即上线，不用排队审核」 | 与生产一致 |

`/book-ad`、提交表单早已说对了，说明这是旧静态站话术没清干净，不是履约逻辑有问题。

**本次统一口径**：

- **付费收录 / 广告位**：付款成功后由系统自动收录发布 / 自动排期，不需要站长经手；
- **免费档**：仍是人工审核，通常 7–14 天、不保证，这段保留；
- **后台「确认收款」按钮**：改名为手动补发类文案，明确它只在回调丢失 / 支付处理器未启用时兜底，**不是主流程**；
- 英文统一 `published automatically as soon as payment succeeds` / `Payment schedules it automatically`，中文统一「付款成功后自动收录发布」「付款成功自动排期」。

## 二、从 launchit.fast 立即抄来的部分

### 2.1 `/pricing` —— 三层漏斗（对应报告 §4.2）

| 新增 | 实现 |
|---|---|
| Step 1 / 2 / 3 卡带 | `#pricing` → `#ads` → `#compound` 三步，同页锚点跳转，不跳站外 |
| 活数字条 | `useAsyncData('pricing-live')` 并发读 `/api/tools` 与两个 `/api/ads/availability`；展示已收录产品数、分类数、未来 6 周可订周次、一次性付费档数 |
| 一次性付费强调 | 数字条下写明「所有档位一次性付费；付费档付款成功后自动收录发布」 |
| 场景导购 | 「不确定选哪个」三张卡：`?plan=standard` / `?plan=featured` / `/book-ad?slot=sidebar` |
| 长期曝光区（Step 3） | `#compound` 三张卡指向 `/weekly`、`/seo-check` 与站内入口，说明「不再付费也持续生效」 |
| FAQPage 结构化数据 | 由 `pricingFaq`（10 条）生成 JSON-LD，和可见折叠问答同源；新增「还要等人工确认吗」「会影响搜索排名吗」两问 |

**没动**：原四档价格、`DirectoryPricingTable`、方案对比表、支付与 checkout 链接、链接政策。价格仍全部由服务端 `planAmountCents()` / `adPriceCents()` 算，不读请求体。

### 2.2 `/pricing#ads` 与 `/book-ad` —— 对应报告 §4.3

- 两处都显示**实时可订周次**，统一读 `GET /api/ads/availability?slot=…&weeks=…`，不会出现「定价页说有、预订页说没」；
- `/book-ad` 加三条信任标：付款成功自动排期 / 一次性付款不自动续费 / 同一周不超卖；
- `/book-ad` 加**可见 FAQ**（4 问）+ 同一数组生成的 FAQPage JSON-LD；
- 接口失败时用 `EMPTY_AD_AVAILABILITY` 直接隐藏数字，**不伪造空位数**。

### 2.3 首页 —— 对应报告 §4.1

新增 `.home-spots` 卡带「两个位置，明码标价」：

- board $29 / sidebar $19 直接露价；
- 显示实时「未来 6 周还有 N 周可订」；
- 两张卡分别直达 `/book-ad?slot=board&weeks=1`、`/book-ad?slot=sidebar&weeks=1`。

### 2.4 明确**不抄**的

| 不抄 | 原因 |
|---|---|
| 竞价 Billboard / 金额叠加 / 同站重复付款升位 | 要改 `ad_booking` 与履约逻辑，属业务模式变更 |
| 「无审核即时上线」写进 Listing 收录 | 我方免费档确实仍需人工审核，写了就是虚假承诺 |
| DR 71 反链话术 / badge 反链互换 | `dirtool.com` 实测 DR4=0 / DR3=0，抄了是虚假宣传 |
| Ask AI 站外深链 | 撞 owner「站内闭环」偏好 |
| 配置化全站促销 / 逐页 `.md` / `/compare` | 需先定服务端算价边界或内容积累，属 P1/P2 |

### 2.5 主动补的、超出原确认范围（**显式标注**）

1. `/pricing` 与 `/book-ad` 的 **FAQPage JSON-LD** 由可见 FAQ 同一数组生成，避免 Google 结构化数据与页面文案不一致；
2. 活数字条与广告区都写了**「不承诺搜索排名 / 流量 / 域名权重」免责声明**（照搬竞品数字营销话术有合规风险）；
3. 首页插入卡带后补了 CSS 间距补偿 `.home-top + .home-spots, .home-spots + .home-layout { margin-top: 34px }`，并给 `.home-spot__cta svg` 显式 14px 兜底（Icon sprite 的 svg 无 intrinsic size，不修会被浏览器按 300×150 撑爆按钮）；
4. **同步清理旧文档**：`docs/01`、`02`、`03`、`04`、`07`、`08`、`09`、`10` 里「人工确认收款 / 确认收款当天」等描述，其中 `docs/08` 的页首状态原本还写着「未接入真实支付」。这部分是我主动补的，owner 只要求改站内文案。
