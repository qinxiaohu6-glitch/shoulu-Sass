## 4. P1 · 承诺了但没兑现

### 4.1 `/seo-check` 后端 ✅ 已完成（2026-11-05）

**当时的现象**：导航（顶栏 + 抽屉 + 页脚）都链到 `/seo-check`，页面也在，但它的两个按钮调 `/api/audit` 和 `/api/dr`——这两个接口在 `server/api/` 里根本没有，点下去必然看到「诊断服务暂时不可用」。

**做了什么**：选了方案 A，把 `legacy/audit.py`（479 行）与 `legacy/drcheck.py`（129 行）移植成 `server/api/audit.post.ts` + `server/api/dr.post.ts`，并把页面里两个 `<div hidden>` 空占位换成真实渲染（`.audit__*` 那套 CSS 在 `legacy.css` 里本来就有，没加新样式）。

**没做方案 B**，因为方案 A 的代价和 B 差不多，而 B 只是把一个坏页面藏起来——用户点进去还是会撞到。

**仍未完成的部分**：DR 需要一个数据源 key（`NUXT_AHREFS_TOKEN` 或 `NUXT_OPENPAGERANK_KEY`）。没配时接口如实返回 `not_configured`，页面说「读不到」并给官方免费查询入口，**不编数字**。详见 `docs/07` §十四。

### 4.2 用户不能编辑已上线的提交

**现象**：旧站有 `POST /api/my/submissions/update`（归属校验 + 改动退回 pending），Nuxt 版没移植。用户想改标题或简介只能发邮件，而你**在后台也改不了正文**——只能拒绝让他重提，或直接改 D1。

**为什么是 P1**：付费用户买的是「一个长期存在的页面」，改不了文案意味着每次小改动都要找人。这是复购意愿的直接杀手。

**要做的事**：

1. `server/api/my/submissions/update.post.ts` — 归属校验（`owner_sub` 必须匹配，或管理员），改完 `status` 退回 `pending`
2. `app/pages/settings/submissions.vue` — 每行加「编辑」，弹出表单
3. 明确一条规则：**已付款的条目编辑后退回 pending，但不影响 `paid_at`**（钱已经收了）

### 4.3 Featured / Pro 的「置顶到期日」要人工补

**现象**：`publicTool()` 把提交来的条目 `featured_until` 设成空字符串——因为「一个展示窗口是排期，而提交没有排期」。后果是：卖了 Featured（7 天置顶）之后，系统不会在 7 天后自动摘置顶。

**现在怎么绕**：卖出去后，在后台「收录管理」手动置顶并设到期日。

**要做的**：确认收款时，按 `plan` 自动写一条 `tool_overrides`（featured → +7 天，pro → +90 天）。改动很小，就在 `confirmPayment()` 里加一步。

### 4.4 没有支付网关

**现象**：用户点「确认支付」只是把记录标成待付款，真实收款靠人工。

**现状（2026-11-05）**：接口已经写好了——provider 抽象、`POST /api/payments/checkout`、
签名校验的 webhook、幂等结算（`WHERE status='pending'`）、金额只从服务端定价表读。
`getPaymentProvider()` 在没配密钥时返回 `null`，付款按钮就不出现，站点安静地留在
人工收款。**只差一个商户号**：配好 `NUXT_PAYMENT_PROVIDER` / `NUXT_STRIPE_SECRET_KEY` /
`NUXT_STRIPE_WEBHOOK_SECRET` 就自动切换。步骤见 `docs/08-在线支付接入.md`。

**为什么还是 P1 不是 P0**：一天几单的时候人工更划算，且流程已经闭环（定价页写明了
「确认收款后当天上线」）。

## 5. P2 · 体验与增长

### 5.1 搜索索引的时效性

搜索框打开时按需拉一次 `/api/tools`，所以新建的提交在同一次会话里要重新打开搜索框才搜得到。影响很小，但「刚上线的产品搜不到」是会被投诉的那类小事。

**改法**：搜索框每次打开都 `refresh()`，或给 `/api/tools` 加一个短 TTL 的 `caches.default` 缓存。

### 5.2 DR 域名权重

定价页现在无法展示「本站 DR xx」这种背书。要打这个卖点必须先接 Ahrefs 或 OpenPageRank，再在 `catalog.json` 的 `site.dr` / `site.dr_verified` 里填真实值。

**注意**：`site.dr` 已经有字段了，**不要填一个没验证过的数字**——这个站的全部差异就是「不编数据」。

**2026-11-05 进展**：查询链路已经通了（`POST /api/dr`，读 `NUXT_AHREFS_TOKEN` 或 `NUXT_OPENPAGERANK_KEY`），只差一个 key。没配时 `/seo-check` 会如实说读不到，所以现在可以先不配、也不会有假数字上墙。接 key 之前记得先补 D1 缓存——旧站有 24h 文件缓存，Workers 没有文件系统，裸接会按点击量烧 API 配额。

### 5.3 认领收录（claim listing）

让提交者用自己的域名邮箱验证「这条是我的」，然后能自己改文案。它和 4.2 是同一件事的两半：4.2 解决「我的提交我能改」，认领解决「我买的那个页面是我的」。

**前置**：4.2 先做完。

### 5.4 数据看板

现在要看数据只能跑 SQL（见 01 文档 §7.2）。一个「本周提交 / 上线 / 收入 / 广告在位」的小面板能省掉每天一次 `wrangler d1 execute`。

**注意**：不要做成竞品那种编造的「2,422 founders visited, up 103%」。每个数字都要能追溯到一张表。

## 6. 明确不做

| 不做 | 原因 |
|---|---|
| 评论 / 评分 | 审核成本 + 防刷机制，收益远低于维护 |
| 收藏 / 关注 | 需要账号体系深度绑定，用户量撑不起 |
| 订阅制 | 提交者明确抗拒；一次性付费决策成本低 |
| 自建支付 | 早期单量小；量起来后接 Stripe/Paddle |
| 编辑团队 / 原创评测 | 人力密集，与「目录」定位冲突 |
| 移动 App | 站点已响应式 |
| 博客 | **2026-11-05 决定暂缓**。内容运营是持续投入，且与「目录」的 SEO 主战场（收录页）抢权重 |
| 用户自定义头像 | Google 是身份源 |

> 原表里有一行「工单系统 · 联系页足够」——2026-11-05 已按源码移植做完，
> 从「不做」挪出。留下这条注记是因为：**「不做」的判断会变**，而改了不写，
> 下次读文档的人会以为它一直没做。
