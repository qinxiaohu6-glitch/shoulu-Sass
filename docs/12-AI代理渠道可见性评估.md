## 二、核实到的事实

### 2.1 skills.sh

来源：[skills.sh](https://www.skills.sh/)、[文档](https://www.skills.sh/docs)、[vercel-labs/skills](https://github.com/vercel-labs/skills)、[creating-skills.md](https://github.com/vercel-labs/skills/blob/main/docs/creating-skills.md)

- 「The Agent Skills Directory」，`npx skills add <owner/repo>` 一行安装；支持 70+ 种 agent。
- **榜单按 `skills` CLI 的匿名 telemetry 排名**（记录「哪个 skill 被安装」，不记录个人信息）⇒ 你贴的「运行一次 `npx skills add`」确实是让它进入统计/榜单的动作。
- 每个 skill 有专属页 `https://www.skills.sh/<owner>/<repo>/<skill>`，显示安装命令与 **installs 计数**；另有 install-count badge：`https://skills.sh/b/<owner>/<repo>`。
- `SKILL.md` = YAML frontmatter（`name`、`description`）+ Markdown 指令；仓库布局 `skills/<name>/SKILL.md`（CLI 扫描三层，也支持仓库根目录）。
- 有「routine security audits」；官方明确不保证每个 skill 的质量/安全。
- **未找到自助提交表单**；文档只写了安装、榜单、packs、badge、安全，没有「submit your skill」入口。

### 2.2 Hermes Plugin Catalog

来源：[plugin-catalog/README.md](https://github.com/NousResearch/hermes-agent/blob/main/plugin-catalog/README.md)、[catalog-submission 文档](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins/catalog-submission)、[示例 0bull.yaml](https://github.com/NousResearch/hermes-agent/blob/main/plugin-catalog/0bull.yaml)

仓库 `NousResearch/hermes-agent` 公开，`plugin-catalog/` 真实存在，条目可用 `hermes plugins catalog` / `search` 发现、`hermes plugins install <name>` 安装。准入规则比转述里严格得多：

1. **Human-merged gate**：只能通过 PR 加 `plugin-catalog/<name>.yaml`，maintainer review 后合并；「no self-serve registry, no automated ingestion」。
2. **必须 pin 完整 40 位 commit SHA**，分支 / tag / short SHA 直接被 loader 拒绝；安装时 clone 并 checkout 到该 commit。
3. **禁止自更新代码**；每次升级都是一个新的 SHA-bump PR，reviewer 会看 commit range。
4. **提交者必须是插件仓库 owner 或主要贡献者**，第三方代投会被 decline。
5. 提交前本机跑 `hermes plugins validate /path/to/plugin --install-deps`，修完所有 failure、读完 warnings；等 catalog CI 绿。
6. PR description 要写：插件做什么、用了哪些 Hermes surfaces、**rule 13 披露**（第三方网络调用、越界读取、shell 命令、后台长进程、凭证存储），有 UI 附截图；同样内容要写进插件 README。
7. `capabilities:` 必须与 pinned commit 实际注册的 tools/hooks/middleware/env 一致，不一致视为安全问题。
8. 每个条目自动生成 `https://hermes-agent.nousresearch.com/docs/plugins/<name>` 页面，渲染 pinned commit 的 README。

### 2.3 对你贴的描述的三点校正

| 你的描述 | 官方实际 |
|---|---|
| 「仓库包含 `plugin.json`、`mcp.json` 和 MCP 技能文件」 | **必需的是 `plugin.yaml` + 至少一个入口**（`__init__.py` / `desktop/plugin.js` / `plugin.json` / `dashboard/manifest.json` 四选一）。`plugin.json` 只是 portable Agent Plugin 的**可选入口之一**；`mcp.json` 与 `skills/` 在提交规范里**不是硬性要求**。 |
| 「在 PR 上发布自安装测试结果，审阅者会特别关注」 | 官方文档**没有这条明文要求**。硬性要求是本地 `validate --install-deps` 全绿 + catalog CI 绿 + PR description 的功能/surfaces/披露。贴自测结果是加分经验，不是规定。 |
| 「不到一天就合并」 | 是对方个例。官方是人审 + CI + 逐条规则核对；**规则 3（自更新）与规则 9（运行时改 Hermes core）违规是直接 decline，不是让你改 bug**。 |
